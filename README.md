# 职镜

> **把面试官的视角，还给你**

职镜是一套面向**全专业**求职学生的 AI 训练工作台。它不只覆盖计算机岗，而是把
**11 个一级大类 / 64 个细分岗位**（含教师、医护、会计、法律、机械、传媒等）
的真实考察逻辑整理成可练习的题库与追问链 —— 不管你学什么专业，都能找到贴近自己目标的训练内容。

## 关键词

`AI Agent` · `职业训练` · `简历诊断` · `面试陪练` · `人机协同`

## 作品概要

职镜把求职准备中最需要"有人指点"的四个环节，做成一条可以自己走完的完整链路：

**简历诊断 → 岗位追问链 → 面试陪练 → 复盘报告**

- 上传简历，得到**逐条可执行的修改清单**（标出简历里的原句、问题在哪、给出改后的句子），而不是笼统的"建议多写数据"
- 选定目标岗位，先看清**面试官会怎么一层层追问**（考察维度 → 首问 → 深挖 → 边界），再进入实战
- 面试陪练过程中，AI 会根据你的回答**自主决定追问、换题还是深挖**，而不是照着题库念
- 结束后生成结构化复盘：总分、逐题分析、Top3 短板与下一步改进计划

## 解决的教育痛点

| 痛点 | 现状 | 职镜的做法 |
|---|---|---|
| **反馈稀缺** | 一次真实面试要等企业安排，失败也不告诉你为什么；学校就业指导一位老师对几百个学生，改不出一份简历 | 把"专业的反馈"变成随时可获取的能力，一次上传即得逐条修改清单 |
| **信息不对称** | 学生不知道目标岗位到底考什么，只能到处搜"面经"，真假混杂 | 把岗位的真实考察逻辑显式画出来——先看清再练，而不是盲目刷题 |
| **练习成本高** | 找同学模拟面试要凑时间，且对方不专业、不敢说真话 | 随时可练、反复可练，且反馈不受人情影响 |
| **专业覆盖窄** | 市面上的 AI 面试工具几乎只做互联网技术岗，非计算机专业学生无人服务 | 覆盖 11 大类 / 64 个细分岗位，教师、医护、会计、法律等专业都有对应内容 |

## 技术创新点

1. **岗位两级体系 + 离线内容兜底**
   11 大类 / 64 细分岗位，每个岗位都配好 **4 个考察维度 + 三层追问链 + 题库**（合计 256 个维度、986 道题）。
   **关键点：没有 AI 密钥也完全可用** —— 追问链走人工整理版、简历诊断走规则版，
   而不是给用户一个报错页。评委和用户都不必先配密钥才能看到产品。

2. **人格化的多步 Agent，而非单轮问答**
   面试官 Agent 具备工具调用能力：检索岗位题库 → 按阶段出题 → 评估回答 → **自主决定追问/换题/深挖**。
   追问链不是预设脚本，而是根据你的回答动态生成。

3. **三层兜底，任何一环失败都不中断体验**
   主模型 → 备用模型 → 规则/离线内容，三层逐级降级。
   实测单次交付成本约 **¥0.09**，并内置成本计量、限流与当日预算闸门。

4. **可量化、可核验的运营数据**
   每一次交付都记录成本、耗时、AI 完成步骤占比与迭代轮次，
   用真实数字而非估算口径回答"这套方案能不能持续跑下去"。

5. **岗位数据可远程热更新**
   岗位与题库是可直接阅读的 JSON，支持打包托管、远程拉取、原子替换，
   内容更新**无需重新发版**；拉取失败则沿用当前数据，不影响使用。

## 落地场景

| 场景 | 用法 |
|---|---|
| **个人求职准备** | 上传简历 → 选定目标岗位 → 看清考察点 → 反复练习 → 复盘改进 |
| **高校就业指导中心** | 作为简历初筛与面试预演的自助工具，把老师的精力留给最需要个别辅导的学生 |
| **院系专业导引课** | 学生选岗前先看该岗位的真实考察逻辑，帮助建立"学什么、考什么"的对应关系 |
| **学院/社团就业活动** | 无密钥也能完整演示，不依赖网络与算力，适合现场体验 |

## 应用成效

**功能规模**（当前版本实测）

| 指标 | 数值 |
|---|---|
| 覆盖岗位 | 11 个一级大类 / 64 个细分岗位 |
| 考察维度 | 256 个（每岗位 4 个） |
| 题库总量 | 986 道，平均每岗位 15 道 |
| 简历解析支持 | PDF / DOCX / TXT / Markdown（含扫描版识别与提示） |

**全链路压测**（两组独立测试 × 各 3 轮 = 6 次完整链路，**中断/报错 0**）

| 指标 | 实测值 |
|---|---|
| 简历诊断平均耗时 | 16.7 秒 |
| 简历诊断平均建议条数 | **13 条**（每条含原句、问题、原因、改后句） |
| 岗位追问链平均耗时 | 22.0 秒 |
| 面试单轮问答平均耗时 | 1.9 秒 |
| 非 AI 环节（岗位数据查询） | 90 毫秒 |
| 单轮可计量 AI 成本 | **¥0.28**（诊断 + 追问链），折合单次交付约 ¥0.09 |

> 口径说明：诊断与追问链的 16~22 秒是**大模型本身的生成时间**，非系统卡顿；
> 非 AI 环节在百毫秒级。两者应分开表述。
>
> 复现方式：`pnpm loadtest`（会真实调用 AI 并产生费用），原始报告见 `tests/reports/`。

**质量保障**

- 端到端回归 `pnpm regression`：**42 项通过 / 0 失败**
- 界面交互检查 `pnpm ui-check`：**27 项通过 / 0 失败**
- 岗位数据校验：**54 项规则**，每次提交前自动跑

## 核心模块

| 模块 | 说明 |
|---|---|
| **简历诊断** | 上传 PDF/DOCX 简历，输出**逐条可执行的修改清单**（原句 → 问题 → 建议改法） |
| **岗位追问链** | 按目标岗位生成**可见的追问树**：岗位 → 考察维度 → 逐层追问节点 |
| **面试陪练** | Agent 多步推理：检索题库 → 出题 → 评分 → 自主决定追问/换题/深挖 |
| **复盘报告** | 结构化报告：总分、通过判断、逐题分析、Top3 短板、改进计划 |
| **训练计划** | 基于历史弱项生成下一阶段训练任务 |
| **题库练习** | 按岗位浏览题目与考察要点，**不依赖 AI**，断网或未配密钥也能用 |
| **求职规划** | 对比目标岗位技能要求，给出差距分析与分阶段学习路径 |

## 快速开始

**环境要求**：Node.js ≥ 20.9、pnpm ≥ 9（`package.json` 已声明 `packageManager`，启用 corepack 后会自动使用对应版本）

```bash
corepack enable     # 首次使用，自动匹配 pnpm 版本（可跳过，只要本机有 pnpm）
pnpm install
pnpm dev            # http://localhost:5000
```

生产构建：

```bash
pnpm build
pnpm start
```

### ⚡ 不需要任何配置就能跑起来

`pnpm dev` 之后直接访问 http://localhost:5000 即可。**不配置任何环境变量也能正常使用**：

| 能力 | 无配置时的表现 |
|---|---|
| 岗位浏览（11 大类 / 64 个细分岗位） | ✅ 正常 |
| 题库练习（986 道题 + 4 维考察要点） | ✅ 正常 |
| 岗位追问链 | ✅ 走**人工整理版**内容 |
| 简历诊断 | ✅ 解析 PDF/DOCX，输出的**规则版**修改清单仍然可执行 |
| AI 面试陪练 / AI 生成内容 | ⚠️ 需配置 API Key（见下） |

这不是"残废状态"：题库与追问链本来就准备了完整的离线内容，
设计上就要求**没有 AI 密钥也是可用的产品**，而不是一个报错页。

### 启用 AI 能力（可选）

复制 `.env.example` 为 `.env.local`，至少填这一项即可：

```env
OPENAI_API_KEY=你的 DeepSeek API Key
OPENAI_BASE_URL=https://api.deepseek.com
INTERVIEW_MODEL=deepseek-flash
ANALYSIS_MODEL=deepseek-flash
```

> 也支持任意 OpenAI 兼容端点（`OPENAI_BASE_URL` 换成智谱 GLM 等即可，
> `.env.example` 里给了两套可直接抄的配置）。
> 请勿将真实密钥提交到仓库；`.env.local` 已在 `.gitignore` 中。

## 环境变量

完整清单与说明见 [`.env.example`](./.env.example)（每一项都写了用途和踩坑提示）。
常用几项：

| 变量 | 是否必需 | 说明 |
|---|---|---|
| `OPENAI_API_KEY` / `OPENAI_BASE_URL` | 可选 | 不填则走离线降级模式 |
| `DATABASE_URL` | 可选 | SQLite 路径，默认 `file:./interview.db` |
| `ADMIN_TOKEN` | 可选 | 岗位管理接口令牌；不配则管理接口整体关闭（默认安全） |
| `STUDIO_PASSWORD` | 可选 | 运营看板口令（内部工具）；不填用内置默认值 |
| `OPC_ROLES_URL` | 可选 | 岗位数据远程热更新地址；不填用随代码发布的 `data/roles/**` |
| `OPC_RATE_LIMIT_PER_HOUR_*` / `OPC_DAILY_BUDGET_CNY` | 可选 | AI 调用限流与当日预算闸门 |

## 自检（改完代码跑一遍，比手点页面可靠）

```bash
pnpm regression          # 端到端回归：数据校验 / 接口 / 简历解析 / 会话隔离 / AI 功能
pnpm regression:offline  # 同上但跳过要调 AI 的用例（快，不花钱）
pnpm ui-check            # 浏览器交互检查（两级选岗、离线入口、看板口令门等）
pnpm ui-check -- --ai    # 同上，并验证结果页反馈条（要调 AI，较慢且计费）
pnpm loadtest            # 全链路压测与取数（会真实调用 AI 并产生费用）
pnpm roles:validate      # 岗位数据 54 项校验规则
```

> `ui-check` 依赖 Playwright。它不是项目依赖（体积大、要下浏览器），
> 所以脚本做成了**能用就跑、不能用自动跳过**，不会阻塞主回归。
> `regression` 与 `ui-check` 都需要服务先跑起来（`pnpm dev`）。
> `--ai` 那组刻意**只验证反馈条是否出现、不点击提交** ——
> 点了会在 `iterations` 表留下非真实用户的记录，而那张表要用于赛事材料。

## 岗位数据（`data/roles/**`）

平台覆盖 **11 个一级大类 / 64 个细分岗位**，数据全部是**可直接阅读的 JSON**：

```
data/roles/
├── taxonomy.json          # 两级分类索引
├── cs-it/                 # 计算机与信息技术（11 个细分岗位）
├── edu-research/          # 教育与科研
├── finance-econ/          # 金融与经济
└── ...                    # 每个子类一个 .json，含题目/考察维度/公司/面经
```

- **校验**：`pnpm roles:validate`（规则在 `src/lib/job-roles/validate.ts`，与运行时共用同一份）
- **远程热更新**：`pnpm roles:bundle` 打包 → 托管 → 配 `OPC_ROLES_URL`，
  之后改内容**无需重新发版**。详见 [`data/roles/README.md`](./data/roles/README.md)
- 内容来源均带 `source` 字段（赛事要求外部数据须说明来源），
  AI 生成的内容会显式标注，不冒充真实面经

## 数据安全与合规

- **匿名会话隔离**：所有数据按会话隔离，互不可见
- **一键删除**：可随时删除本会话全部数据
- **人工复核**：所有 AI 生成内容标注状态，需用户确认后方视为定稿
- **来源声明**：使用的模型、平台、题库数据来源均在各处显式说明
